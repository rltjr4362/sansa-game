# 산사의 하루 — LLM NPC 게임 설계 스펙

- 작성일: 2026-11-25
- 원본: `docs/review/original.html` (`~/Downloads/파스텔 버전 2.html` 복사본, Codex 제작, 수정 금지)
- 설계 검토: Codex `gpt-6.2-sol` 2라운드 (`docs/review/`)

## 1. 목표

원본 산사 시뮬레이션을 **키보드로 플레이하는 브라우저 게임**으로 바꾼다. 플레이어가 NPC에게 말을 걸면 **브라우저 안에서 도는 로컬 LLM**이 한국어로 답하고, 대화에 따라 NPC가 실제로 행동한다. 친구에게 **링크 하나**로 공유하며 설치는 없다.

### 성공 기준 (MVP)
1. GitHub Pages 링크를 Chrome/Edge 데스크톱에서 열면 즉시(모델 없이) 플레이된다.
2. 방문객을 WASD/방향키로 움직이고, 벽·연못·전각을 통과하지 못한다.
3. 스님 2타일 내에서 E → 대화창. 자유 한글 입력 또는 1/2/3 추천 대사로 말한다.
4. "모델 받기" 동의 후 Qwen3.5-2B가 로드되면, 스님이 LLM으로 답하고 "연못 같이 가요" 같은 말에 실제로 따라오거나 이동한다.
5. 스님이 부탁 1종을 제안하고, 플레이어가 실제로 수행하면 게임이 완료를 판정해 호감도를 올린다.
6. Q로 스님에 빙의해 조종하고, 다시 Q로 해제하면 스님이 현재 위치에서 일과를 이어간다.
7. 새로고침해도 호감도·만남 횟수·부탁 기록이 남는다.
8. 플레이 중 30fps 이상 유지(M4 Pro 기준), LLM 응답 중에도 끊김이 체감되지 않는다.

## 2. 범위

| 단계 | 포함 |
|---|---|
| **MVP** (완성 즉시 친구 공유) | 방문객 이동·충돌, E 상호작용, 대화창(자유 입력 + 추천 3개), LLM 행동 5종, 부탁 1종, 스님 빙의/해제, 대본 선제 인사, 호감도·사실 기억 저장, WebLLM + Mock, GitHub Pages |
| **2단계** (업데이트) | 동물(황구·백구·고양이) 빙의, 동물 발화(빙의 시·호감도 높을 때), 하루 일지(J), 모델 선택 UI(0.8B/2B/4B), Ollama, 부탁 추가, 종루 이스터에그 |
| **범위 밖** | NPC끼리 LLM 대화, 모바일 터치 이동, 세이브 슬롯 |

### 종루 이스터에그 (2단계)
종루에서 E(또는 우하단 山 도장 5회 클릭) → 타종음 + 화면 흔들림 → 산문에서 꼬마 캐릭터 3종이 걸어 들어와 마당을 돌고 퇴장. 캐릭터는 **원본 픽셀 그림체의 오리지널 디자인**(특정 IP 캐릭터 복제 금지, 공개 배포이므로). 디자인은 Codex/GPT.

## 3. 구조

빌드 없는 브라우저 ES 모듈, GitHub Pages 정적 배포. 모델 가중치는 WebLLM 기본 호스트(Hugging Face)에서 받는다.

```
index.html
src/world.js        원본 Temple (DOM 무관, Node에서도 실행)
src/render.js       원본 Scene + 방문객·말풍선·상호작용 표시
src/viewer.js       원본 viewer + 플레이 카메라
src/contracts.js    NPC 스냅샷·행동 요청 타입 (두 작업자의 접점)
src/lines.js        페르소나·대본·템플릿 문구
src/player.js       입력·이동·상호작용·빙의
src/control.js      조종권 이전 (빙의 시작/해제)
src/actions.js      행동 요청 검증·실행
src/brain.js        NPC 스냅샷 → 프롬프트 → 응답 파싱
src/memory.js       localStorage 기록
src/errands.js      부탁 템플릿·완료 판정
src/dialogue.js     대화창 UI
src/llm/index.js    LLM.chat({messages, schema, signal})
src/llm/webllm.js   WebWorker 엔진
src/llm/mock.js     대본 응답
tests/              Node 테스트 (world/actions/brain/memory, Mock LLM)
```

**경계 규칙**
- `world.js`, `render.js`는 LLM을 모른다.
- `brain.js`는 DOM을 모른다.
- LLM 출력은 `actions.js` 검증을 통과해야만 세계에 반영된다.
- 두 작업자의 접점은 **NPC 스냅샷**(brain 입력)과 **검증된 행동 요청**(actions 입력) 두 타입뿐이다.

**모듈 분리 시점**: 처음부터 전부 쪼개지 않는다. 작업용 `index.html`에서 플레이 흐름을 먼저 연결하고, DOM 독립이 확인된 `Temple`부터 추출한다. Scene/viewer 경계는 플레이 흐름 검증 뒤에 자른다.

## 4. 플레이어·빙의·카메라

### 이동
- WASD/방향키, 연속 이동. 화면 방향 → 월드 방향 변환은 현재 카메라 각도 사용. **MVP에서는 플레이 중 시점 회전을 고정**(관찰 모드에서만 회전).
- 충돌: 발 좌표를 `Math.floor`로 타일화해 `walkable(x,y)` 검사. 이동 중 통과하는 모든 타일도 검사. 대각선 모서리·법당 문턱을 테스트 케이스로 둔다.

### 상호작용
- E: 거리 2타일 이내 **이면서** A* 경로 길이 4타일 이하인(벽 너머 제외) 가장 가까운 NPC. 대상 위에 "E 말걸기" 표시.

### 빙의 = 조종권 이전
- 세계 tick은 계속 돈다. 시계·날씨·농사·손님·동물은 멈추지 않는다.
- 빙의 시작: 대상이 참여 중인 공동 행동(`s.meeting`, `dog.visitor`, `group.pair`, `s.encounter`)을 종료한다. 현재 일과는 **목적지 id만 보관**하고 `path`는 버린다.
- 빙의 중: 대상의 자동 이동·일과 진행·완료 처리를 건너뛴다. 위치는 플레이어 입력으로만 바뀐다. 방문객은 그 자리에 서서 대기한다(다른 NPC가 말 걸 수 있는 대상).
- 해제: 보관한 목적지로 **현재 타일에서 재탐색**. 도달 실패 시 `choose()`로 새 일과. 다른 장소에서 일과 완료 처리가 일어나지 않아야 한다.
- 합격 기준: 스님–황구 만남 진행 중 스님에 빙의해도 황구가 대기 상태에 갇히지 않고, 해제 후 스님이 새 위치에서 일과를 이어간다.

### 렌더
- 방문객과 빙의 대상 모두에 대해 정의한다: (1) 방 점유(실내 단면 열기), (2) 실내·실외 중 한 번만 그리기, (3) 컷어웨이(가림 창) 대상. 원본은 스님/손님/백구·고양이를 경로별로 다루므로(`original.html:1255`, `:1284`, `:1327`, `:1353`) 통일된 "주인공" 개념으로 정리한다.

### 카메라
- `selected`(상호작용 대상)와 카메라 대상을 분리한다.
- 플레이 모드: 플레이어(또는 빙의 대상) 추적이 기본. 관찰 모드(기존 휠·핀치·장소 선택)는 명시 전환(Tab).
- 캔버스·말풍선·클릭 영역은 같은 카메라 변환을 사용한다.

## 5. NPC 두뇌

### 호출 시점
- 플레이어 발화 시에만 LLM 호출 (MVP). 선제 인사는 **대본**: 플레이어 3타일 내 + 스님 일과가 idle/look/rest + 쿨다운 60s → 대본 인사 말풍선.

### 응답 스키마 (WebLLM JSON 문법 강제)
```json
{
  "say": "string, ≤60자",
  "action": "none | follow | stop_follow | go_to | offer_errand",
  "place": "대웅전 | 연못가 | 우물 | 들밭 | 산문 | 앞마당 | null",
  "options": ["≤20자", "≤20자", "≤20자"]
}
```
- `place`는 `go_to`일 때만 의미. 부탁 내용은 게임이 고른다(LLM은 제안 여부만).
- 스파이크에서 `go_to` 장소 정확도가 낮으면 `go_to`를 2단계로 미룬다.
- `options` 누락·검증 실패 시 상황별 템플릿 3개.

### 프롬프트 (작게)
- system: 페르소나 1~3줄 + 규칙(짧게, 한국어 존댓말, 행동 목록) 
- context: 시각·날씨·현재 장소·스님 일과·진행 중 부탁·만남 횟수·호감도 구간
- history: 직전 1~2턴

### 행동 실행 (actions.js)
- 사전검사: 거리, 경로 존재, 현재 공동 행동, 빙의 여부. 실패 시 `none`으로 강등하고 대사는 유지.
- `follow`: 스님 일과를 보류하고 플레이어 뒤 1~2타일 유지, 60s 또는 `stop_follow`까지.
- `go_to`: 해당 장소 접근 타일로 경로 이동. 플레이어가 같이 가면 도착 시 대본 한마디.
- `offer_errand`: 진행 중 부탁이 없을 때만. 대화창에 [수락]/[거절].

### 요청 수명
- 요청마다 id. 8s 타임아웃, 대화 종료, 빙의 전환 시 `interruptGenerate()`.
- 응답 도착 시 id·대화 상대·거리·부탁 상태를 다시 확인. 어긋나면 폐기.
- 실패·타임아웃·스키마 위반 → Mock 응답.

## 6. 기억·부탁·호감도

- 저장(localStorage, 키 `sansa.v1`): NPC별 `{meetings, affinity, errands:{offered, accepted, done}, lastLines:[최근 2턴]}`.
- 호감도는 **게임 이벤트로만**: 대화 1회 +1(하루 상한 3), 부탁 완료 +5. LLM은 호감도를 바꾸지 못한다.
- 부탁 1종 (MVP): "우물에서 물 한 바가지 길어 와 주세요" — 우물(28,9) 2타일 내 E로 물 받기 → 스님에게 E로 전달 → 완료. 보상은 완료 이벤트에서 한 번만.
- 프롬프트에는 호감도 구간(처음 봄/낯익음/친함)과 만남 횟수만 넣는다.

## 7. LLM 런타임

- 기본: WebLLM `0.2.89`, WebWorker 엔진, 모델 `Qwen3.5-2B-q4f16_1-MLC`(파일 약 1.08GB, VRAM 약 2.2GB). non-thinking 모드 확인.
- 비교 후보: `gemma-4-E2B-it-q4f16_1-MLC`(VRAM 약 3.4GB, `shader-f16` 필요). 한국어 품질이 크게 나을 때만 교체.
- 로딩: 화면의 "AI 스님 깨우기(약 1GB)" 버튼 → 진행률 → 완료 전까지 Mock.
- 감지: `navigator.gpu` → 어댑터 요청 → 필요한 기능·버퍼 한도 → 엔진 초기화 성공까지 확인. 어느 단계든 실패하면 Mock 모드 + 안내 문구.
- 대체 런타임(Transformers.js v4, MediaPipe, wllama)은 WebLLM에서 재현되는 문제가 있을 때만 비교.

## 9. 테스트

- **기준선**: 원본 `Temple`을 Node `vm`으로 같은 시드 720초 실행 → 일과 순서·수확·손님 체류 기록. 변경 후 빙의 미사용 시 동일해야 한다.
- **Node 단위·통합** (Mock LLM): 충돌(대각선·문턱), 상호작용 대상 선택, 빙의 시작/해제 합격 기준, actions 사전검사·강등, 늦은 응답 폐기, 부탁 보상 1회, 호감도 상한, 저장/복원.
- **스파이크 측정** (localhost + 실제 Pages URL, 같은 한글 입력 20개): JSON 유효율, 상황에 맞는 행동 선택률, 한국어 대사 품질(사람 평가 1~5), 첫 토큰·완료 시간, Mock 전환율, 플레이 중 프레임 시간. Qwen3.5-2B vs Gemma 4 E2B, `options` 포함/미포함.
- **브라우저 수동 체크리스트**: 성공 기준 1~8.
