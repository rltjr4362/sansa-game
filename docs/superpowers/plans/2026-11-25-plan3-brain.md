# Plan 3 — 두뇌·행동·기억·부탁·연결 (담당: Claude)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. TDD, 작은 커밋.

**Goal:** 스님이 로컬 LLM(Gemma 4 E2B, WebLLM)으로 한국어로 답하고 행동 5종을 실행하며, 우물 부탁 1종·호감도·사실 기억을 갖게 한다. Plan 2의 `Play`에 꽂히는 `createGame(play)`를 만든다.

**스펙:** §5 두뇌, §6 기억·부탁·호감도, §7 런타임, §8 오류. 결정: `docs/spike/2026-11-25-results.md` (Gemma 기본, 대사 먼저 스트리밍 후 추천, go_to 유지, 예열 요청, 인사말 반복 금지, 대화 이력 투입).

**계약:** `src/contracts.js` — `parseReply`, `REPLY_SCHEMA`, `PLACES`, `affinityBand`, `NpcSnapshot`, `ActionRequest`, `MonkHandle`, `DialogueView`, `Play`. **바꾸지 않는다.**

**작업 위치:** worktree `~/Projects/sansa-game-brain`, 브랜치 `plan3-brain`. Plan 2(Codex)의 소유 파일(`index.html`, `src/render.js`, `src/viewer.js`, `src/player.js`, `src/control.js`, `src/dialogue-view.js`, `src/play.js`)은 만들지 않는다. `src/game.js`는 이 계획이 진짜 구현을 소유한다(Plan 2에는 echo 임시본).

모든 모듈은 DOM에 의존하지 않는다(`src/llm/webllm.js` 제외). Node 테스트에서 가짜 객체로 검증한다.

### Task 1: `src/lines.js`

내보내기:
- `MONK_NAME = '도연 스님'`
- `SYSTEM_RULES: string` — 스파이크 `spike/prompts.js`의 SYSTEM을 기반으로 다음을 추가: "‘어서 오십시오’ 같은 인사말을 대화 중간에 반복하지 않는다", "방문객의 말에 직접 답한다", "대사와 action이 서로 맞아야 한다(따라가겠다고 말하면 follow)".
- `PERSONA: string` — 도연 스님 1~3줄(차분, 유머 약간, 산사의 일과를 아낌).
- `greetingFor({clock, weather, meetings}): string` — 대본 선제 인사. 비/밤/아침/첫 만남/재방문 분기. 결정적(같은 입력 → 같은 출력).
- `openingFor({meetings, affinityBand}): string` — E로 말 걸었을 때 스님의 첫 줄(LLM 없이).
- `templateOptions({following, errandState}): string[3]` — 상황별 추천 3개.
- `MOCK`: `{greet, follow, stopFollow, goTo(place), errand, fallback}` 대사 문자열들.
- `ERRAND = {id:'water', offer, accepted, declined, atWell, delivered, hudAccepted, hudCarrying}` 문구.

테스트: 모든 문자열이 비어 있지 않고 60자 이하(`Intl.Segmenter` 기준), `templateOptions`는 항상 3개·각 20자 이하, `greetingFor` 결정성, 비 오는 날 인사에 비 관련 단어 포함.

### Task 2: `src/memory.js`

```
createMemory(storage = globalThis.localStorage, now = () => Date.now()) → {
  get(npc) → {meetings, affinity, errands:{offered, accepted, done}, lastLines: Array<{role,content}>}
  recordMeeting(npc)              // meetings+1, 대화 1회 호감도 +1 (하루 상한 3, 하루 = now()의 로컬 날짜)
  recordErrand(npc, kind)         // kind: 'offered'|'accepted'|'done'. done이면 호감도 +5
  pushLine(npc, role, content)    // lastLines 최대 4개(2턴) 유지
  band(npc) → affinityBand(affinity)
}
```
- 저장 키 `sansa.v1`, 값 JSON `{version:1, npcs:{...}}`. 매 변경 후 저장.
- storage가 없거나 getItem/setItem이 throw하면 메모리 내에서만 동작(예외 전파 금지).
- 손상된 JSON → 빈 상태로 시작.

테스트: 가짜 storage(Map 기반)로 저장·재생성 후 복원, 하루 상한 3(같은 날 5번 → +3, 다음 날 +1 더), done +5, lastLines 4개 유지, throw하는 storage에서도 동작, 손상 JSON.

### Task 3: `src/errands.js`

```
createErrands(memory) → {
  state() → 'none'|'offered'|'accepted'|'carrying'|'done'
  offer() → boolean      // none 또는 done일 때만 → offered, memory.recordErrand('monk','offered')
  accept() → boolean     // offered → accepted
  decline() → boolean    // offered → none
  atWell() → boolean     // accepted → carrying
  deliver() → boolean    // carrying → done, memory.recordErrand('monk','done') 정확히 1회
  snapshot() → null|{id:'water', state:'offered'|'accepted'|'carrying'}
}
```
테스트: 정상 흐름, 순서 위반은 false·상태 불변, deliver 두 번 호출해도 보상 1회, done 후 다시 offer 가능, snapshot 형태.

### Task 4: `src/llm/mock.js`

```
createMockLLM() → { kind:'mock', ready:true, chat({messages, signal, onText}) → Promise<string> }
```
- 마지막 user 메시지에서 키워드로 행동 결정: 따라와/따라오/같이 걸/뒤로 → follow; 그만 따라/기다려/여기서 잠깐 → stop_follow; PLACES 이름 또는 별칭(연못→연못가, 밭→들밭, 법당→대웅전) + 가/보러/데려 → go_to; 도울/시킬/일손/심부름 → offer_errand; 그 외 none.
- 대사는 `lines.MOCK`, 추천은 `templateOptions`. 반환은 `REPLY_SCHEMA`를 만족하는 JSON 문자열.
- `onText`가 있으면 결과 전체를 한 번 호출. `signal.aborted`면 `AbortError`로 reject.

테스트: `spike/prompts.js`의 PROMPTS 20개 중 18개 이상 기대 행동 일치, 모든 결과가 `parseReply`로 null이 아님, abort.

### Task 5: `src/llm/router.js`

```
createRouter({primary, fallback, timeoutMs = 8000}) → {
  active() → 'llm'|'mock'           // primary?.ready ? 'llm' : 'mock'
  chat({messages, signal, onText}) → Promise<{raw: string, reply: Reply, source: 'llm'|'mock'}>
}
```
- primary가 없거나 ready=false → fallback.
- primary 호출에 자체 AbortController 연결(외부 signal abort 시 같이 abort). timeoutMs 초과 시 abort 후 fallback.
- primary 결과를 `parseReply` → null이면 fallback.
- 외부 signal이 abort되면 fallback도 부르지 않고 `AbortError` reject.
- fallback 결과도 parseReply. (Mock은 항상 유효해야 한다)

테스트(가짜 엔진): 정상, 미준비→mock, 예외→mock, 타임아웃(가짜 타이머 또는 timeoutMs:20)→mock이고 primary signal이 aborted, 파싱 실패→mock, 외부 abort→reject·fallback 미호출.

### Task 6: `src/brain.js`

```
buildMessages(snapshot: NpcSnapshot, userText: string) → Array<{role, content}>
```

### Task 7: `src/actions.js`

```
applyAction(monk: MonkHandle, request: ActionRequest, ctx: {errands, followSeconds = 60}) →
  {executed: 'none'|'follow'|'stop_follow'|'go_to'|'offer_errand', reason?: string}
```
사전검사: `monk.possessed()` 또는 `monk.busy()` → none(reason). follow: 이미 following이면 none. stop_follow: following 아니면 none. go_to: `monk.goTo(place)` false면 none. offer_errand: `errands.offer()` false면 none. 예외를 던지지 않는다(monk 메서드가 던져도 none).

테스트: 가짜 MonkHandle로 각 행동·각 강등 사유, 던지는 monk.

### Task 8: `src/llm/webllm.js` + `src/llm/worker.js`

```
createWebLLM({modelId = 'gemma-4-E2B-it-q4f16_1-MLC', onProgress}) → {
  kind:'webllm', ready:false,
  supported() → Promise<boolean>     // navigator.gpu && requestAdapter() && (modelId가 f16이면 shader-f16)
  load() → Promise<void>             // CreateWebWorkerMLCEngine, onProgress(0~1, text), 끝나면 예열 요청 1회(max_tokens 8), ready=true
  chat({messages, signal, onText}) → Promise<string>
    // stream:true, temperature 0.7, max_tokens 160, response_format {type:'json_object', schema: JSON.stringify(REPLY_SCHEMA)}
    // Qwen 계열이면 extra_body {enable_thinking:false}
    // signal abort → engine.interruptGenerate() 후 AbortError
}
```
WebLLM `@mlc-ai/web-llm@0.2.89`를 `https://esm.run/`에서 import. Node 테스트 없음(브라우저 확인은 Task 10). 이 파일은 Node에서 import되지 않게 game.js가 동적 import 한다.

### Task 9: `src/game.js`

```
createGame(play: Play, deps = {}) → {dispose()}
  // deps: {memory, router, brain, errands, loadWebLLM}  (테스트 주입용, 없으면 기본 생성)
```
동작:
1. **선제 인사:** onTick에서 방문객 조종 중 + 대화창 닫힘 + 스님과 맨해튼 거리 ≤3 + `!monk.busy() && !monk.possessed() && !following` + 마지막 인사 후 60초 → `monk.say(greetingFor(...))`.
2. **E→스님:** `dialogue.open(MONK_NAME)`, `memory.recordMeeting`, 부탁이 carrying이면 → `errands.deliver()`, `dialogue.setNpcText(ERRAND.delivered)`, hud 비움. 아니면 `openingFor(...)`. 추천은 `templateOptions`. 상태 줄: router.active()==='mock'이면 "대본 스님이 답해요 · 우상단에서 AI 스님을 깨울 수 있어요".
3. **onSubmit(text):** requestId 증가·활성화, 이전 요청 abort, `setThinking(true)`, `setOptions([])`, `setChoices([])`. `brain.ask` → onSay로 `setNpcText`. 결과의 requestId가 활성과 다르면 무시. `setThinking(false)`, `setNpcText(reply.say || '…')`, 추천은 `reply.options ?? templateOptions`. 스냅샷은 `monk.snapshotBase()` + memory + errands. `applyAction` 실행, `offer_errand` 실행 시 `setNpcText(reply.say)` 뒤 `setChoices([{label:'수락',id:'accept'},{label:'거절',id:'decline'}])`. memory.pushLine user/assistant.
4. **onChoice:** accept → `errands.accept()`, `setNpcText(ERRAND.accepted)`, hud `ERRAND.hudAccepted`; decline → `ERRAND.declined`.
5. **E→우물:** accepted면 `errands.atWell()`, hud `ERRAND.hudCarrying`, `monk.say`는 하지 않음(멀리 있음). 아니면 아무것도 안 함.
6. **onClose / onPossessChange:** 활성 요청 abort·무효화. 빙의 전환 시 대화창이 열려 있으면 close.
7. **모델 버튼:** `play.modelButton(click)` 텍스트 "AI 스님 깨우기 (약 2.7GB)". 클릭 → supported() false면 setText("이 기기에선 대본 스님"), true면 load, 진행률 "깨우는 중 37%", 완료 hide, 실패 setText("깨우기 실패 · 대본 스님").

테스트(가짜 Play·DialogueView·MonkHandle, Mock router): 선제 인사 조건·쿨다운, E→대화창 열림·첫 줄, 제출→대사·추천 표시, follow 실행, offer_errand→선택지→수락→우물→전달→호감도 +5(memory 확인), 대화창 닫은 뒤 도착한 응답 무시(지연 엔진), 빙의 전환 시 close 호출.
