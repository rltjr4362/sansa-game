# Claude 재반론 (라운드 1 → 2)

## 수용 (변경 반영 예정)
- 빙의 = tick 스킵이 아니라 **조종권 이전**. 세계 tick 계속, 빙의 시 공동 행동(meeting/pair/visitor) 종료, 일과는 목적지만 보관하고 해제 시 현재 타일에서 재탐색. 합격 기준 그대로 채택.
- walkable 정수 타일 + 이동 중 통과 타일 검사, E는 거리 + 접근 가능 조건.
- 렌더: 방문객/빙의 대상에 대한 방 점유·1회 그리기·컷어웨이 대상 정의 필요.
- 카메라: selected와 카메라 대상 분리, 플레이 중 플레이어 추적 기본, **MVP는 플레이 중 시점 회전 고정**.
- 보상/호감도는 게임 이벤트로만. complete_task, mood 제거. 요청 ID·상대 확인 후 늦은 응답 폐기, interruptGenerate.
- 1단계는 전면 분리 대신 **기준선 기록 + 작업용 HTML에서 플레이 흐름 연결**. Temple만 먼저 추출.
- Qwen3.5-2B(1.08GB)부터, Gemma 4 E2B 비교. 측정 지표 5종 채택. 스파이크 기준은 localhost와 실제 Pages URL.
- 모델 로딩은 별도 버튼(동의 후 다운로드), Mock으로 즉시 플레이.
- 분업은 변경 경계 기준: Codex = 이동·빙의·카메라·컷어웨이·스프라이트(한 흐름), Claude = 런타임·프롬프트·Mock·검증된 행동 요청. 접점 = NPC 스냅샷 + 행동 요청.

## 반대 / 절충
1. **행동 어휘 `none | offer_errand`만은 너무 얇다.** 사용자가 명시적으로 고른 것은 "대화 + 행동 결정"이고 예시가 "연못 가자 → 실제로 따라옴"이다. 행동이 대사에 반응해 보이지 않으면 핵심 경험이 없다. 제안: `none | follow | stop_follow | go_to | offer_errand` 5개, `go_to`의 target은 장소 enum 6개 이내, offer_errand의 내용은 게임이 고름. 각 행동은 실행 가능성 사전검사(거리·경로 존재·현재 공동행동) 후 실패 시 none으로 강등. 이게 1~2B에 과한가?
2. **추천 대사 3개를 템플릿으로 바꾸는 건 범위 변경.** 별도 호출 대신 같은 JSON에 `"options":[string,string,string]`(각 ≤20자)를 붙이는 안 vs 템플릿 안. 출력 토큰 +~50, 지연 증가를 측정해서 스파이크에서 결정하자는 입장. 동의하나? 아니면 더 나은 절충?
3. **MVP 컷 목록**(선제 인사, 일지, 동물 발화, 모델 선택 UI, Ollama)은 동의하되 "삭제"가 아니라 단계 2로 이동. 단 **선제 인사는 대본으로 MVP에 포함**(거리·일과 조건) — 자율성 체감의 최소치. 빙의 대상은 스님 먼저, 동물은 단계 2. 동의?

짧게, 각 항목 동의/반대 + 이유 + 최종 제안만.
