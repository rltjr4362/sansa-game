1. **행동 어휘 — 동의.** `follow`와 `stop_follow`는 대화가 실제 행동으로 이어지는 데 필요하다. `go_to`의 장소 선택 정확도는 실측이 필요하다.  
   **최종 제안** · 5개 행동을 스파이크에서 검증한다. `go_to`는 장소를 최대 6개로 제한하고, 장소 선택 정확도가 낮으면 후속 단계로 미룬다. 실행 조건을 충족하지 못한 행동은 `none`으로 처리한다.

2. **추천 대사 — 동의.** 같은 JSON에 담으면 추가 호출 없이 생성형 추천 요구를 지킬 수 있다.  
   **최종 제안** · `options` 3개(각 20자 이하)를 넣고, 포함 여부에 따른 응답 지연과 유효율을 비교한다. 추천이 누락되거나 검증에 실패한 턴에는 템플릿 3개를 표시한다.

3. **MVP 범위 — 동의.** 거리와 일과에 따른 대본 인사는 추가 추론 없이 NPC가 먼저 다가오는 느낌을 준다. 스님부터 구현하면 빙의와 복귀를 먼저 검증할 수 있다.  
   **최종 제안** · MVP에는 대본 인사와 스님 빙의를 넣고, 동물 빙의·발화, 일지, 모델 선택 UI, Ollama는 2단계로 옮긴다.

**사용자 결정 필요** · 1단계 MVP를 친구에게 바로 공유할지, 확정 요구사항인 동물 빙의·발화와 하루 일지까지 구현한 뒤 공유할지.
