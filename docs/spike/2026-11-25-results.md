## 발견한 버그 (수정 완료)
Qwen3.5는 thinking을 꺼도 JSON 앞에 빈 `<think>\n\n</think>`를 붙인다. 첫 실행에서 JSON 유효율이 0%로 나와 발견했고, `parseReply`가 맨 앞 think 블록 하나를 벗기도록 고쳤다(커밋 2503083).

관찰: Qwen은 문장이 자주 깨지고 행동 판단도 약하다. Gemma는 문장이 자연스럽고 행동은 잘 고르지만, "어서 오십시오"로 시작하는 버릇이 있고 대사가 행동과 안 맞을 때가 있다(6, 9번). 원인은 프롬프트 맥락의 "처음 만났다"와 대화 이력이 없는 점. Plan 3 프롬프트에서 인사말 반복을 금지하고 직전 대화를 넣어 다룬다.

## 결정 규칙 적용

1. JSON 유효 95% 미만 탈락: 해당 없음 (모두 통과).
2. 기본 모델: Gemma의 완료 시간은 Qwen의 1.33배(5,582 / 4,206) → 1.5배 이하 조건 충족. **사용자 품질 점수에서 Gemma가 1점 이상 높으면 Gemma.** → 사용자 평가 대기
3. 추천 생성: 추천을 넣으면 완료 시간이 Gemma +45%, Qwen +52% → 40% 기준 초과 → **규칙상 템플릿.** → 사용자 확인 대기 (확정 요구사항과 충돌)
4. go_to: Gemma 100% → **유지**.
5. 최악 프레임 간격 > 100ms → **Plan 3에 생성 중 렌더 부하 대책(예열 요청, 생성 중 프레임 측정) 추가.**

## 사용자 결정 (2026-11-25)
- 대사 발췌와 수치를 보고 **Gemma 4 E2B**를 기본 모델로 선택. 다운로드가 크지만 행동 정확도와 한국어 자연스러움을 우선.
